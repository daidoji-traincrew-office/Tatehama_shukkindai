# UC-12 運転会用のダイヤ・行路を編集する

## 概要
運転会作成時にデフォルトからコピーしたダイヤと行路を、その運転会に合わせて編集する。変更はコピーにだけ加わり、デフォルト（UC-10）には反映されない。コピーは出勤台の確定時にアーカイブされる（UC-21、確定方法は保留）。

## 主アクター
- 主催者
- 共同主催者

## 関係アクター
- APIサーバー（権限判定、バージョン照合、保存）

## トリガー
- 主催者または共同主催者が、運転会の画面からダイヤ・行路の編集を開く

## 事前条件
- デスクトップアプリにログイン済み（UC-01）
- 運転会が作成済み（UC-11）
- 操作者がその運転会の主催者または共同主催者である
- 出勤台が未確定である（確定後の修正の扱いは保留）

## 基本フロー
1. 操作者が運転会のダイヤ・行路編集画面を開く。
2. システムは運転会用のダイヤ（コピー）と、それぞれの行路を表示する。表示時点のバージョンを保持する。
3. 操作者は以下を行う。
   - ダイヤ内の列車の追加・変更・削除（保持する項目は UC-10 の Q-10-1 に従う）
   - 行路の追加・削除、行路の列車番号リストの編集（列車の追加・削除・並べ替え）
   - 行路の識別子の変更
4. 操作者が保存する。
5. システムは入力を検証する（検証内容は UC-10 の Q-10-3 に従う）。
6. システムは保存時のバージョンを照合する。一致すれば保存し、バージョンを進める。
7. システムは更新後のダイヤ・行路を表示する。行路の希望（UC-15）や出勤台（UC-17）は更新後の内容を参照する。

## 代替フロー
- A1 デフォルトのダイヤを追加でコピーする：作成時にコピーしなかったデフォルトダイヤを後から運転会に取り込む（可否は Q-12-3 参照）。
- A2 運転会用ダイヤをデフォルトの最新内容で取り直す：要判断事項 Q-12-3 参照。

## 例外フロー
- E1 権限なし：主催者・共同主催者以外が保存しようとした場合、API が拒否する。
- E2 バージョン不一致（同時編集）：手順6で一致しない場合は保存せず、後から保存した人に警告して最新を読み込み直させる（出勤台と同じ扱い。適用範囲は Q-12-4 参照）。
- E3 検証エラー：保存せずに該当箇所を示す。
- E4 割り当て済み・希望済みの行路や列車を削除・変更しようとした：要判断事項 Q-12-1 参照。
- E5 確定済みの運転会：編集を受け付けない（確定後の修正は保留）。
- E6 通信エラー：保存せずにエラーを表示し、入力内容はアプリ上に残す。

## 事後条件
- 運転会用のダイヤ・行路（コピー）が更新され、バージョンが進んでいる。
- デフォルトのダイヤ・行路は変わっていない。

## 扱うデータ（エンティティと主な項目）
- 運転会用ダイヤ（コピー）：ID、運転会ID、コピー元デフォルトダイヤID、名前、列車の一覧、バージョン
- 運転会用行路（コピー）：ID、運転会用ダイヤID、コピー元デフォルト行路ID、識別子、列車番号の順序付きリスト
- 参照：行路の希望（UC-15）、出勤台の列車ごとの担当（UC-17/UC-20）

## 通知
- なし（要件定義書の通知一覧に該当なし）。変更を希望者に知らせるかは Q-12-2 参照。

## 権限チェック
- その運転会の主催者または共同主催者のみ編集可（事業本部の扱いは Q-12-5 参照）。
- デフォルト側は編集できない（デフォルトは事業本部のみ。UC-10）。
- 判定は API 側で行う。

## 関連UC
- UC-10 デフォルトのダイヤ・行路を編集する
- UC-11 運転会を作成する（コピーの作成）
- UC-15 行路の希望を表明・取り消す
- UC-16 人気行路を抽選する（抽選タイミングは保留）
- UC-17 出勤台の枠に人を割り当てる
- UC-21 出勤台を確定しアーカイブする（確定方法は保留）

## 要件定義書の該当箇所
- 用語集「ダイヤ」「行路」
- 出勤台 > 行路・ダイヤ（運転会ごとの変更はコピーにだけ加える、確定時にコピーごとアーカイブ、変更できるのは主催者と共同主催者）
- 出勤台 > 枠の割り当てと編集（保存時のバージョン照合）
- 出勤台 > 最終状態の保存（確定方法は保留）

## 要判断事項
- Q-12-1 既に希望（UC-15）や担当者の割り当て（UC-17）がある行路・列車を削除・変更した場合の扱い。
  - 選択肢：(a) 削除・変更を禁止する（先に割り当てを外させる） (b) 警告を出して確認後に実行し、該当の希望・割り当ても削除する (c) 警告を出して実行し、割り当ては「対象なし」として残し出勤台側で直させる
  - 推奨：(b)。準備中の変更は頻繁にありうるので禁止は不便。確認ダイアログで影響する人を表示すれば事故を防げる。
- Q-12-2 行路の内容が変わったとき、その行路に希望を出していた人に知らせるか。
  - 選択肢：(a) 知らせない（要件どおり） (b) アプリ上で希望一覧に「変更あり」を表示する (c) Bot から DM する
  - 推奨：(b)。通知一覧に無い DM は増やさず、アプリ内の表示で足りる。
- Q-12-3 作成後にデフォルトダイヤを追加で取り込む、またはデフォルトの最新内容で取り直す機能を設けるか。
  - 選択肢：(a) どちらも設けない (b) 追加の取り込みのみ設ける (c) 追加の取り込みと取り直し（運転会側の変更を破棄）の両方を設ける
  - 推奨：(b)。作成時の選び忘れを救済できる。取り直しは割り当てとの整合が複雑になるので見送る。
- Q-12-4 バージョン照合の単位。
  - 選択肢：(a) 運転会単位で1つのバージョン（ダイヤ・行路・出勤台・区割りすべて共通） (b) ダイヤ・行路の編集で1つ、出勤台で1つと分ける (c) ダイヤごとに分ける
  - 推奨：(b)。主催者がダイヤを直している間に共同主催者が出勤台を編集できる。出勤台が参照する行路の削除は Q-12-1 の確認で扱う。
- Q-12-5 事業本部が、主催者・共同主催者でない運転会のダイヤ・行路を編集できるか。
  - 選択肢：(a) できない（要件どおり主催者・共同主催者のみ） (b) 救済用にできる
  - 推奨：(a)。要件に明記がなく、必要なら事業本部を共同主催者に加えれば対応できる（ただし共同主催者は指令員・指令員見習いロールが必要な点に注意）。
