# UC-11 運転会を作成する

## 概要
運転会を1件作成し、種別（A：体験版／B：本格的な運転会）、日時、主催者・共同主催者を登録する。作成時にデフォルトのダイヤと行路をその運転会用にコピーし、以降の運転会ごとの変更はコピーにだけ加える（UC-12）。

## 主アクター
- 主催者（指令員ロールを持つ人）

## 関係アクター
- 共同主催者（指令員または指令員見習いロールを持つ人。登録される側）
- 事業本部（作成できるかは要判断事項 Q-11-1 参照）
- APIサーバー（権限判定、コピー処理、保存）
- Discord Bot（ロールの確認）

## トリガー
- 指令員ロールを持つ人がデスクトップアプリで運転会の新規作成を選ぶ

## 事前条件
- デスクトップアプリにログイン済み（UC-01）
- 操作者が指令員ロールを持っている（事業本部の扱いは Q-11-1 参照）
- デフォルトのダイヤ・行路が1つ以上登録されている（UC-10）。0件の場合は Q-11-3 参照

## 基本フロー
1. 操作者が運転会の新規作成画面を開く。
2. 操作者は以下を入力する。
   - 運転会名（要否は Q-11-2 参照）
   - 種別：A または B
   - 開始日時・終了日時（日本時間。日付をまたぐ場合は開始日を開催日とする）
   - 主催者：既定は操作者本人
   - 共同主催者：0人以上（人数の上限は Q-11-4 参照）
3. 操作者はコピーするデフォルトダイヤを確認する（全部か選択かは Q-11-3 参照）。
4. 操作者が保存する。
5. システムは入力を検証する。
   - 種別が A/B のいずれか
   - 終了日時が開始日時より後
   - 主催者が指令員ロールを持つ
   - 共同主催者が指令員または指令員見習いロールを持つ
   - 主催者・共同主催者がデスクトップアプリにログイン済み（社員番号発番済み）
6. システムは運転会を作成し、対象のデフォルトダイヤと、それに属する行路を運転会用にコピーする。運転会と同一トランザクションで保存する。
7. システムは作成した運転会の画面を表示する。以降、主催者・共同主催者は UC-12・UC-13・UC-14 で準備を進める。

## 代替フロー
- A1 共同主催者を後から追加・削除する、運転会の日時・種別を変更する、運転会を中止・削除する：要判断事項 Q-11-5 参照。
- A2 主催者を操作者以外にする：手順2で別の指令員を主催者に指定する（可否は Q-11-1 参照）。

## 例外フロー
- E1 権限なし：操作者が指令員ロールを持たない場合（Q-11-1 で事業本部を許可した場合を除く）、API が拒否する。
- E2 ロール不適合：主催者・共同主催者に指定した人が必要なロールを持たない場合、保存せずに該当者を示す。
- E3 未ログインの人を指定：アプリに一度もログインしていない人は候補に出さない（選択肢に表示されない）。
- E4 日時不正：終了日時が開始日時以前の場合、保存しない。
- E5 コピー失敗：コピー中にエラーが起きた場合、運転会の作成ごと取り消す（中途半端な運転会を残さない）。
- E6 通信エラー：保存せずにエラーを表示する。

## 事後条件
- 運転会が作成され、主催者・共同主催者が登録されている。
- 運転会用のダイヤ・行路のコピーが作られている。以後デフォルトを編集してもこのコピーは変わらない。
- 公開設定は既定値（希望人数：非公開、誰が希望したか：非公開）で作られる（UC-14）。
- 信号区割り・シフト枠は未設定（UC-13）。

## 扱うデータ（エンティティと主な項目）
- 運転会：ID、名前、種別（A/B）、開始日時、終了日時、開催日（開始日の日本時間の日付）、状態（準備中など。確定に関わる状態は保留）、作成者、作成日時、バージョン
- 運転会の主催者・共同主催者：運転会ID、Discord ユーザーID、区分（主催者／共同主催者）
- 運転会用ダイヤ（コピー）：ID、運転会ID、コピー元デフォルトダイヤID、名前、列車の一覧
- 運転会用行路（コピー）：ID、運転会用ダイヤID、コピー元デフォルト行路ID、識別子、列車番号の順序付きリスト
- 公開設定：運転会ID、希望人数の公開可否（既定 非公開）、希望者の公開可否（既定 非公開）

## 通知
- なし（要件定義書の通知一覧に該当なし）。作成の告知を Discord に流すかは Q-11-6 参照。

## 権限チェック
- 作成：指令員ロール（事業本部は Q-11-1 参照）
- 主催者の指定：指令員ロールを持つ人のみ
- 共同主催者の指定：指令員または指令員見習いロールを持つ人のみ
- 判定は API 側で、その時点のロール情報に基づいて行う。

## 関連UC
- UC-01 ログインする
- UC-10 デフォルトのダイヤ・行路を編集する（コピー元）
- UC-12 運転会用のダイヤ・行路を編集する
- UC-13 信号区割りと信号・指令シフト枠を設定する
- UC-14 公開設定を変更する
- UC-17 出勤台の枠に人を割り当てる
- UC-21 出勤台を確定しアーカイブする（確定方法は保留）

## 要件定義書の該当箇所
- 対象運転会（A・B）
- アクター > 運転会ごとの役割（主催者、共同主催者）
- 見習い期限（日付をまたぐ運転会は開始日を開催日とする）
- 出勤台 > 行路・ダイヤ（作成時にデフォルトをコピー）
- 出勤台 > 行路の希望と抽選 > 公開設定（デフォルト値）

## 要判断事項
- Q-11-1 運転会を作成できるのは誰か。主催者を操作者以外に指定できるか。
  - 選択肢：(a) 指令員ロールを持つ人のみ。作成者が主催者になる (b) 指令員ロールを持つ人＋事業本部。作成時に主催者（指令員）を指定できる (c) (a)＋主催者を別の指令員に指定可
  - 推奨：(b)。代理作成や運用上の救済ができる。主催者は必ず指令員ロール保持者とする点は要件どおり維持できる。
- Q-11-2 運転会名を必須にするか。
  - 選択肢：(a) 必須 (b) 任意（未入力なら「開催日＋種別」を表示） (c) 持たない
  - 推奨：(b)。同日に複数開催された場合の区別に使え、入力の手間もない。
- Q-11-3 作成時にコピーするデフォルトダイヤの範囲。
  - 選択肢：(a) デフォルトダイヤをすべてコピー (b) 作成時に1つ以上を選んでコピー (c) 1つだけ選んでコピー
  - 推奨：(b)。使わないダイヤが出勤台に混ざらず、複数ダイヤを使う運転会にも対応できる。デフォルトが0件なら作成不可とするか空で作るかも併せて決める（推奨：空で作成可、UC-12 で追加）。
- Q-11-4 共同主催者の人数上限。
  - 選択肢：(a) 上限なし (b) 上限あり（例：3人）
  - 推奨：(a)。要件に制限がなく、権限も主催者と同等で区別の必要がない。
- Q-11-5 作成後の運転会情報（日時・種別・共同主催者・主催者）の変更、運転会の中止・削除を本UCに含めるか、どう扱うか。
  - 選択肢：(a) 主催者・共同主催者が確定前なら変更・削除可（削除は出勤台が空のときのみ） (b) 変更可・削除は不可で「中止」状態にする (c) 変更・削除とも事業本部のみ
  - 推奨：(b)。記録は消さない方針（非機能要件）に合い、中止した運転会は集計から外せばよい。種別の A→B 変更は最終参加日に影響するため確定前に限る。
- Q-11-6 運転会の作成を Discord に告知するか。
  - 選択肢：(a) しない（要件どおり） (b) 告知チャンネルに投稿する
  - 推奨：(a)。要件定義書の通知一覧に無く、Bot の役割は通知とロールチェックに絞られている。必要になれば後から追加する。
- Q-11-7 主催者は運転会内で指令員を務めるとあるが、作成時に主催者を指令シフト枠へ自動で割り当てるか。
  - 選択肢：(a) 自動で割り当てる（UC-13 の指令枠を1つ作り主催者を入れる） (b) 自動では入れず、UC-13/UC-17 で手で割り当てる
  - 推奨：(b)。長時間の運転会では時間帯で交代するため、固定で入れると後で直す手間が出る。割り当て漏れは出勤台の画面で警告すればよい。
