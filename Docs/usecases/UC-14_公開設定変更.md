# UC-14 公開設定を変更する

## 概要
運転会ごとに、行路の希望に関する情報を参加者へ公開するかを設定する。設定できるのは「希望人数」と「誰が希望したか」の2項目で、どちらも既定は非公開。「当選者がどの行路に入ったか」は必ず公開で、設定の対象外。

## 主アクター
- 主催者
- 共同主催者（主催者と同等の権限を持つため。Q-14-1 参照）

## 関係アクター
- APIサーバー（権限判定、保存、閲覧時の公開範囲の適用）
- 行路の希望を表明する人（UC-15。設定の影響を受ける側）

## トリガー
- 主催者または共同主催者が運転会の画面から公開設定を開く

## 事前条件
- デスクトップアプリにログイン済み（UC-01）
- 運転会が作成済み（UC-11。作成時に公開設定は既定値で作られている）
- 操作者がその運転会の主催者（または共同主催者）である

## 基本フロー
1. 操作者が公開設定画面を開く。
2. システムは現在の設定を表示する。
   - 希望人数：公開／非公開
   - 誰が希望したか：公開／非公開
   - 当選者がどの行路に入ったか：公開（固定・変更不可として表示）
3. 操作者は「希望人数」「誰が希望したか」をそれぞれ切り替える。
4. 操作者が保存する。
5. システムは設定を保存する。
6. 以降、参加者が行路の希望状況を見たとき（UC-15）、API は保存された設定に従って希望人数・希望者を返すか決める。

## 代替フロー
- A1 変更せずに閉じる：何も保存しない。

## 例外フロー
- E1 権限なし：主催者（・共同主催者）以外が変更しようとした場合、API が拒否する。
- E2 「当選者の行路」を非公開にしようとした：アプリでは操作できず、API に送られても拒否する。
- E3 変更できない時期の変更：要判断事項 Q-14-2 参照。
- E4 通信エラー：保存せずにエラーを表示する。

## 事後条件
- 運転会の公開設定が更新されている。
- 参加者への希望状況の表示が、新しい設定に従う。

## 扱うデータ（エンティティと主な項目）
- 公開設定：運転会ID、希望人数の公開可否（既定 非公開）、希望者の公開可否（既定 非公開）、更新者、更新日時
- 参照：行路の希望（UC-15）、抽選結果・出勤台の割り当て（UC-16/UC-17）

## 通知
- なし（要件定義書の通知一覧に該当なし）

## 権限チェック
- 変更：その運転会の主催者（共同主催者は Q-14-1 参照）。
- 閲覧時の制御は API 側で行う。非公開の項目は、権限のない人へのレスポンスに含めない（アプリ側で隠すだけにしない）。
- 非公開でも見られる人の範囲は Q-14-3 参照。

## 関連UC
- UC-11 運転会を作成する（既定値で作成）
- UC-15 行路の希望を表明・取り消す（設定に従って表示）
- UC-16 人気行路を抽選する（抽選タイミングは保留。当選者の行路は必ず公開）
- UC-17 出勤台の枠に人を割り当てる

## 要件定義書の該当箇所
- 出勤台 > 行路の希望と抽選 > 公開設定（運転会ごとに主催者が決める、各項目の既定値、当選者の行路は必ず公開）
- アクター > 運転会ごとの役割（主催者：公開設定、共同主催者：主催者と同等の権限）
- UI（閲覧範囲の判定は API 側）

## 要判断事項
- Q-14-1 公開設定を変更できるのは主催者のみか、共同主催者も含むか。要件定義書は「運転会ごとに主催者が決める」とする一方、「共同主催者は主催者と同等の権限を持つ」とある。
  - 選択肢：(a) 主催者と共同主催者 (b) 主催者のみ
  - 推奨：(a)。共同主催者は同等の権限とされており、例外を作る理由が要件に見当たらない。
- Q-14-2 公開設定を変更できる時期。
  - 選択肢：(a) 確定前ならいつでも変更可 (b) 希望受付の開始前（希望が1件も無い間）のみ変更可 (c) いつでも変更可だが、希望が出た後に非公開→公開へ変える場合は警告する
  - 推奨：(c)。「非公開だと思って希望した人の名前が後から公開される」ことを防ぐ確認を入れつつ、運用の柔軟さを残す。
- Q-14-3 非公開のとき、誰なら見られるか。
  - 選択肢：(a) その運転会の主催者・共同主催者のみ (b) (a)＋事業本部 (c) (a)＋事業本部＋指導運転士
  - 推奨：(b)。主催者・共同主催者は割り当てに必要。事業本部はシステム全体の管理者なので含める。本人は自分の希望を常に見られる。
- Q-14-4 「希望人数」を非公開、「誰が希望したか」を公開にする組み合わせを許すか（希望者が見えれば人数も分かってしまう）。
  - 選択肢：(a) 許さない（希望者を公開にすると希望人数も公開になる） (b) 許す（各項目は独立）
  - 推奨：(a)。矛盾した設定を防げる。
