# UC-13 信号区割りと信号・指令シフト枠を設定する

## 概要
運転会ごとに、信号扱者の担当エリア（信号区割り：どの駅を誰が担当するかのまとまり）を決め、信号・指令の担当枠を開始・終了時刻つきで作る。基本は運転会1回につき担当固定（枠1つ）で、長時間の運転会では時間帯で枠を分けて交代できる。枠に人を入れるのは UC-17、途中離脱による終了時刻の短縮は UC-20 で扱う。

## 主アクター
- 主催者
- 共同主催者

## 関係アクター
- APIサーバー（権限判定、検証、バージョン照合、保存）

## トリガー
- 主催者または共同主催者が、運転会の画面から信号区割り・シフト枠の設定を開く

## 事前条件
- デスクトップアプリにログイン済み（UC-01）
- 運転会が作成済み（UC-11）
- 操作者がその運転会の主催者または共同主催者である
- 出勤台が未確定である（確定後の修正の扱いは保留）

## 基本フロー
1. 操作者が信号区割り・シフト枠の設定画面を開く。
2. システムは現在の信号エリアとシフト枠を表示する。初回は空で表示する（テンプレートからの読み込みは保留）。
3. 操作者は信号エリアを作成する。エリアごとに名前と担当駅を指定する（駅の指定方法は Q-13-1 参照）。全駅を1エリアとして1人で担当する設定も可能。
4. 操作者は信号エリアごとにシフト枠を作る。担当固定なら運転会の開始日時〜終了日時の枠を1つ作る（基本形）。時間帯で交代する場合は、開始・終了時刻を指定して複数の枠に分ける。
5. 操作者は指令のシフト枠を同様に作る。担当固定なら運転会の開始日時〜終了日時の枠1つ（同時に何人の指令員を置くかは Q-13-4 参照）。
6. 操作者が保存する。
7. システムは検証する（枠の時刻が運転会の時間内か、開始＜終了か、同じエリア内の枠の重なり・隙間の扱い、駅の重複・漏れの扱い。詳細は Q-13-2、Q-13-3 参照）。
8. システムは保存時のバージョンを照合し、一致すれば保存する。

## 代替フロー
- A1 既存のエリア・枠を変更・削除する：手順3〜5で変更・削除して保存する。人が割り当て済みの場合は Q-13-5 参照。
- A2 枠を分割する：既存の枠を指定時刻で2つに分ける（交代を後から入れる場合）。元の枠の割り当ての扱いは Q-13-5 参照。
- A3 区割りのテンプレートを保存・読み込みする：**保留**（要件定義書 未決事項）。

## 例外フロー
- E1 権限なし：主催者・共同主催者以外が保存しようとした場合、API が拒否する。
- E2 検証エラー：開始≧終了、運転会の時間外など。保存せずに該当箇所を示す。
- E3 バージョン不一致（同時編集）：後から保存した人に警告して読み込み直させる（照合の単位は UC-12 の Q-12-4 と合わせる）。
- E4 確定済みの運転会：編集を受け付けない（確定後の修正は保留）。
- E5 通信エラー：保存せずにエラーを表示する。

## 事後条件
- 運転会の信号エリアと、信号・指令のシフト枠が保存されている。
- 出勤台（UC-17）で、各枠に信号扱者・指令員（見習い＋指導員を含む）を割り当てられる状態になっている。

## 扱うデータ（エンティティと主な項目）
- 信号エリア：ID、運転会ID、名前、担当駅の一覧、表示順
- シフト枠：ID、運転会ID、種別（信号／指令）、信号エリアID（信号のみ）、開始日時、終了日時
- 参照：運転会の開始日時・終了日時（UC-11）、枠への割り当て（UC-17）
- 集計での利用：個人の出勤履歴に「信号の区割り・時間帯」として出る（UC-23）

## 通知
- なし（要件定義書の通知一覧に該当なし）

## 権限チェック
- その運転会の主催者または共同主催者のみ設定可。
- 判定は API 側で行う。

## 関連UC

- UC-17 出勤台の枠に人を割り当てる
- UC-20 出勤台を直接書き換える（途中離脱による終了時刻の短縮）
- UC-21 出勤台を確定しアーカイブする（確定方法は保留）
- UC-23 個人の出勤履歴を見る

## 要件定義書の該当箇所
- 信号・指令シフト（担当固定、開始・終了時刻つきの枠、途中離脱は終了時刻を早める、エリアごとに複数人、区切り方は主催者が自由に設定）
- アクター > 運転会ごとの役割（主催者：信号区割りの設定）
- 未決事項（信号区割りのテンプレート保存の要否：保留）

## 要判断事項
- Q-13-1 担当駅をどう指定するか（駅マスタを持つか）。
  - 選択肢：(a) 事業本部が管理する駅マスタから選ぶ (b) 駅名を自由入力 (c) 駅は持たず、エリア名（例：「立浜〜新野崎」）の自由入力のみ
  - 推奨：(c)。要件は「区切り方を自由に設定」で、記録に必要なのは「どの区割りを担当したか」。駅単位の検証が不要なら最も軽い。駅単位の集計が必要になったら (a) に拡張する。
- Q-13-2 同じ信号エリア・指令の枠どうしで時刻の重なりや隙間があった場合の扱い。
  - 選択肢：(a) 重なりはエラー、隙間は警告 (b) どちらも警告のみ（保存可） (c) 検証しない
  - 推奨：(b)。引き継ぎのための重なりや、意図的な無人時間もありうる。出勤台の「指導員なし」警告と同じく、保存は止めない。
- Q-13-3 駅の重複（2エリアに同じ駅）や担当漏れを検証するか（Q-13-1 で駅を持つ場合のみ）。
  - 選択肢：(a) 重複・漏れとも警告 (b) 検証しない
  - 推奨：(a)。保存は止めず気付けるようにする。
- Q-13-4 指令のシフト枠に同時に複数人（複数の指令員）を置けるか。
  - 選択肢：(a) 指令は同時に1枠のみ (b) 同時刻に複数の指令枠を作れる（主催者＋共同主催者が並んで指令を務める等）
  - 推奨：(b)。主催者と共同主催者がともに指令員を務めるケースに対応できる。
- Q-13-5 人が割り当て済みの枠を削除・時刻変更・分割した場合の割り当ての扱い。
  - 選択肢：(a) 割り当て済みの枠は削除不可、時刻変更は可 (b) 警告して実行し、削除なら割り当ても外す。分割なら前半の枠に割り当てを残す (c) 警告して実行し、分割時は両方の枠に同じ人を残す
  - 推奨：(b)。UC-12 の Q-12-1 と同じ方針にそろえる。分割は交代の準備なので、後半は空にして新しい担当者を入れさせる。
- Q-13-6 運転会の開始・終了日時を変更した場合（UC-11 の Q-11-5）、既定のまま（運転会の全時間）の枠を自動で追従させるか。
  - 選択肢：(a) 追従させる（運転会の全時間をカバーする枠のみ） (b) 追従させず、時間外になった枠を警告する
  - 推奨：(b)。自動変更は意図しない記録のずれを生む。警告で直させる。
