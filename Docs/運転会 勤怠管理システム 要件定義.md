# 運転会 勤怠管理システム 要件定義

## 用語集

| 用語 | 定義 |
| --- | --- |
| ダイヤ | その運転会で走らせる全列車の時刻表。列車番号ごとに発着時刻や折り返しが決まっている |
| 行路 | ダイヤを運転士1人分ずつに分けたもの。担当する列車を列車番号で指定する（例：新野崎発の各停で立浜へ行き、折り返しの新野崎行きも担当） |
| 出勤台 | 運転会1回分の、誰がどの行路・信号・指令の枠に入るかをまとめた表。1つの枠に見習いと指導員が一緒に入ることがある。将来は運転士＋車掌の2人乗務も想定する |
| 正業 | 見習いを卒業し、その役職を1人で担当できるようになった状態 |

## 目的

- 見習いの幽霊部員化を防ぐため、役職ごとに参加期限を管理する
- 現行の出勤台の機能を移行し、出勤記録の保存・集計を行う
- 既存の運転会システムとは完全に切り離して新規に作る

## 対象運転会

- A（体験版）・B（本格的な運転会）の両方で使う
- 見習い期限の最終参加日は、B運転会の実際の出勤記録でのみ更新する（Aへの参加は数えない）

## アクター

### Discordロール（何ができるかを示す）

- 見習い運転士 / 運転士
- 信号扱者見習い / 信号扱者
- 指令員見習い / 指令員
- 指導運転士
- 輸送指導
- 事業本部（管理者）：システム全体を管理する

### 運転会ごとの役割（ロールの範囲内から割り当てる）

- 運転士・信号扱者・指令員：持っているロールの範囲内で、運転会ごとに担当を決める
- 主催者：指令員ロールを持つ人がなり、運転会内では指令員を務める。運転会の作成、行路・ダイヤ・信号区割りの設定、途中離脱・途中参加の承認と書き換え、公開設定を担う
- 共同主催者：指令員または指令員見習いがなれる。主催者と同等の権限を持つ
- 指導運転士・輸送指導：運転会ごとに割り当て、見習い1人に指導員が1人つく
  - 1人の指導員が複数の見習いを同時に担当することも可能にする（実際はほぼない）
- 指導員として入った回も、そのロールの出勤記録・最終参加日として数える

## 権限

- Discordのロールを権限の基準とする
- 出勤台の枠に入れられるのは、デスクトップアプリにログイン済みで、かつその役職の見習いロールまたは正業ロールを持つ人のみ
- 正業への昇格は、指導員からの要望を受けて管理者がDiscordロールを手で変更する
- 出勤記録の閲覧範囲
  - 本人：自分の記録のみ
  - 指導運転士：運転士・見習い運転士の記録
  - 輸送指導：信号扱者・指令員（各見習い含む）の記録
  - 事業本部：すべての記録

## UI

- Discord Bot：通知とロールのチェックのみを担当する
- C#製のデスクトップアプリ：それ以外の操作（ダイヤ・行路・信号区割り・出勤台の編集、行路の希望、途中離脱・途中参加の申請と承認、記録の閲覧）はすべてここに集約する
  - 対応OSはWindowsのみ（Traincrew自体がWindows専用のため）
  - ログインはDiscord OAuth
  - アプリはDBに直接接続せず、APIサーバーを経由する。閲覧範囲の判定はAPI側で行う
  - GitHub Releasesで配布し、起動時に最新版を確認する。APIが対応する最低バージョンより古いアプリはログインできない

## 社員番号

- システム内部ではDiscordのユーザーIDで人を識別し、社員番号は後から付く項目として扱う
- デスクトップアプリに初回ログインしたときに自動で発番する
- 8桁：年3桁＋月2桁＋連番3桁（年月は初回ログインした年月）
- 番号は維持し、退会者の番号は再利用しない
- Discordサーバーを退会した人は、記録と社員番号を残して「退会済み」とし、期限管理の対象から外す。再入会した場合は以前の番号を使う

## 見習い期限

- 最終参加日は役職ごとに記録する（例：運転士として最後に参加した日、信号扱者として最後に参加した日）
- 「参加」とは、Bの出勤台の最終状態にその役職で載っていること。途中で抜けた人も、担当した部分があれば参加に数える
- 期限の起点は、その役職の最終参加日。まだ一度も参加していない場合は、見習いロールが付いた日
- 日付は日本時間で数える。起点から暦の上で3ヶ月後の日に再スタートし、その15日前にリマインドする（例：最終参加が8月10日なら、リマインドは10月26日、再スタートは11月10日）。日付をまたぐ運転会は開始日を開催日とする
- 再スタート（自動で処理する）
  - 見習いの進捗は各指導員が管理し、システムでは管理しない
  - システムは、期限切れになった役職の見習いロールだけを外す（社員番号は維持）
  - 指導者用チャンネルと本人のDMに通知し、それを受けて指導員が進捗をリセットする
  - 見習いロールが付け直されたら、その日から新しく3ヶ月を数える
- 2.5ヶ月時点（再スタートの15日前）のリマインド
  - 運転士の見習い分は指導運転士向け、信号・指令の見習い分は輸送指導向け
  - 送り先は指導者用チャンネルにまとめて投稿
- ロールの変化の検知
  - Botはロールの付与・削除をその場で拾って記録する
  - Botの起動時に全メンバーのロールと突き合わせ、停止中に見逃した変化を拾い直す
  - 見習いロールと正業ロールを両方持っているなどの矛盾は、管理者に通知する

## 出勤台

### 行路・ダイヤ

- ダイヤは名前をつけて複数の種類を持てる
- 行路は「列車番号のリスト」として持ち、発着時刻は持たない（「何ダイヤの何列車を担当したか」が記録に残ればよい）
- デフォルトの行路・ダイヤを設定・編集できる
- 運転会を作るとき、デフォルトのダイヤと行路をその運転会用にコピーする。運転会ごとの変更はコピーにだけ加え、確定時にコピーごとアーカイブする（デフォルトを後から編集しても過去の記録は変わらない）
- 変更できるのは主催者と共同主催者

### 枠の割り当てと編集

- 見習いを指導員なしで枠に入れた場合は、警告を出す（保存はできる）
- 主催者と共同主催者が同時に編集した場合は、後から保存した人に警告して読み込み直させる（保存時にバージョンを照合する）

### 行路の希望と抽選

- 行路の希望を表明できる
- 人気行路は抽選する
- 抽選のタイミング（手動か締切時刻での自動か）：**保留**
- 公開設定（運転会ごとに主催者が決める）
  - 希望人数：デフォルトは非公開
  - 誰が希望したか：デフォルトは非公開
  - 当選者がどの行路に入ったか：**必ず公開**

### 途中離脱・途中参加

- 本人が申請して主催者が承認するルート
- 主催者が直接出勤台を書き換えるルート（急な離脱向け）
- 両方に対応する
- 途中離脱・途中参加・行路分割は、すべて「行路の中の列車ごとに担当者を記録する」1つの仕組みで表す（例：運転士Xが2列車目で抜け、Yが3列車目から引き継いだ場合、X：1〜2列車目、Y：3列車目〜最後）
- 途中で抜けた人も、担当した部分があれば参加として数える

### 行路分割

- 駅ではなく、行路内の途中の列車（ダイヤ）で区切る（頻度は低い）
- 分割した場合は担当者全員の最終参加日を更新する

### 最終状態の保存

- 出勤台の最終状態をアーカイブとして保存し、出勤記録の集計に使う
- 確定の仕方（誰が・いつ確定するか、確定後の修正、確定し忘れたときの扱い）：**保留**

## 信号・指令シフト

- 基本は運転会1回につき担当固定
- 長時間の運転会では時間帯で交代できるよう、開始・終了時刻つきの枠として持つ
- 途中離脱した人は、枠の終了時刻を早めて表す
- 信号扱者は担当エリアごとに複数人（近い数駅のまとまりが多い。まれに全駅を1人で担当）
- 担当駅の区切り方は主催者が運転会ごとに自由に設定する

## 通知（Bot）

1. 2.5ヶ月のリマインド：指導者用チャンネルへ
2. 再スタートの実施：指導者用チャンネルと本人のDMへ
3. 途中離脱・途中参加の申請：主催者と共同主催者のDMへ
4. 申請の承認・却下の結果：本人のDMへ
5. ロールの矛盾：管理者へ

行路の当選結果を本人にDMで送るかは、抽選のタイミングが決まってから決める。

## 集計

- 人ごと・役職ごとの最終参加日・期限日・B運転会への参加回数の一覧（A運転会への参加は、別の列に回数だけ出す）
- 1人の出勤履歴（運転会、ダイヤ、担当した列車、または信号の区割り・時間帯）
- 運転会ごとの確定済み出勤台
- グラフや統計は後から追加する

## 非機能要件

- 記録は長期間保持し、消えないようにする
- DBは現在のサーバーと同じマシンに置く
- APIはCloudflareのDNS Proxy経由で公開し、サーバーマシンの既存のリバースプロキシを使う
- バックアップ
  - メイン：毎日1回DBダンプを取り、Oracleのオブジェクトストレージへ送る。30日分を残し、それより古いものは月1つだけ長く残す
  - 補助：出勤台を確定するたびに、Discordにダンプを投稿する（容量制限やチャンネル削除のリスクがあるため補助扱い）
  - 数ヶ月に一度、別の環境にダンプを戻して、復元できるかを確認する
- 個人情報保護法の対象になる情報は持たない見込み（ハンドルネーム程度）

## おもしろ機能：アルコール検査

- デスクトップアプリのみで実装し、サーバー側の処理はなし
- ごく低い確率で検知音を鳴らし、画面を赤くする
- 「酒飲んでますモード」を選ぶと必ず検知される
- 完全に演出のみで、出勤処理には一切影響しない
